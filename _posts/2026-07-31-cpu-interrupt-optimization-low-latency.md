在微秒级延迟预算下，延迟主要来自中断与异常对执行流的打断。本文介绍四种针对中断的 CPU 优化手段——CPU 隔离、关中断、大页内存、内核旁路——各自的实现方式、解决的问题与原理。

## 中断的分类

| 类别 | 来源 | 典型代价 |
|------|------|----------|
| 周期时钟中断（tick） | 内核定时器，每秒数百次 | 每次打断执行流，μs 级抖动 |
| 外设硬件中断（IRQ） | 网卡收包、NVMe 完成通知 | 打断 CPU + 上下文切换，μs 级 |
| 软中断（softirq） | 硬中断的下半部，如 NET_RX | 再次抢占当前任务，μs 级 |
| 处理器间中断（IPI） | 调度、负载均衡、RCU、TLB shootdown | 目标核执行流被中断 |
| 系统调用 / 异常 | 每次 read/write、page fault | 用户态↔内核态切换，百 ns~μs 级 |

> 系统调用和 page fault 属于"异常"，但对执行流的干扰机制与中断相同（打断执行流、破坏 cache 局部性），归为一类处理。

## CPU 隔离：消除调度器 IPI 与周期性 tick

**怎么做**：内核参数 `isolcpus` / cpuset 将核心移出通用调度器的管理范围，配合 `nohz_full` 使隔离核进入 tickless，配合 `rcu_nocbs` 将 RCU 回调转移到 housekeeping 核，最后用 `sched_setaffinity` 将业务线程绑定到隔离核：

```
isolcpus=2,3 nohz_full=2,3 rcu_nocbs=2,3
```

**解决什么问题**：tick 每秒数百次打断执行流；调度器负载均衡通过 IPI 在核心间迁移任务；任务抢占与 RCU IPI 造成执行流中断。

**原理**：隔离核不再接收其他任务、不参与负载均衡，消除任务抢占与调度 IPI；tickless 模式消除周期性时钟中断；RCU 回调转移后不再向隔离核发送 IPI。

## "关中断"：用户态所能控制的范围

用户态进程无法直接关闭 CPU 的中断：`cli` 是 ring0 特权指令，用户态执行会触发 #GP 异常。低延迟语境下的"关中断"实际是三个层级的操作：

- **内核模块层**：`local_irq_save()` / `local_irq_restore()` 关闭当前 CPU 的中断响应，用于内核/驱动代码保护临界区；代价是临界区内不能睡眠，关闭窗口应尽可能短。
- **应用层：减少外部中断源**：通过 irq affinity 将外设 IRQ 绑定到其他核心，或通过 Onload 等用户态网络栈将数据收发路径移至用户态（busy polling 保留中断路径，但可降低中断处理频率）。
- **消除周期性 tick**：即 `nohz_full`。

## 大页内存：消除 TLB miss 与运行期 page fault

大页解决两类问题：

- **TLB miss（微架构层）**：hugepage 通常设置为 2MB 或 1GB——2MB 大页使单页覆盖范围扩大 512 倍，显著降低 TLB miss 率；1GB 大页可让 TLB 覆盖全部工作集，命中率趋近 100%，避免了每次 miss 时多级页表遍历（page walk）的几十周期开销。
- **运行期 page fault（异常层）**：默认 4KB 页配合惰性分配，首次访问（touch）才触发 page fault 分配物理页，在用户态执行流中插入一次异常处理并伴随锁竞争。启动阶段通过大页 + `mlock` 预分配并锁定物理内存，可使运行期零 fault、零换页。

> 低延迟系统通常显式关闭 THP（透明大页）：后台线程 `khugepaged` 会定期执行页合并，引入周期性抖动。大页改用 `hugetlbfs` 显式管理。

## 内核旁路（Bypass）：消除硬中断、软中断与系统调用

传统网络路径中，一次收包需要经过**硬件中断 → 软中断（NET_RX）→ 系统调用**三次执行流中断（见下图），每次都伴随上下文切换与数据拷贝。

![传统内核路径的三次执行流中断]({{ site.baseurl }}/assets/images/cpu-interrupt-paths.svg)

**内核旁路（bypass）**：通过 Onload 等用户态网络栈，将数据收发路径从内核移至用户态，避免中断与系统调用开销；或以 io_uring 批量提交请求、减少 syscall 次数。

> bypass 的完整实现原理（Onload 用户态协议栈、io_uring 的 SQPOLL 模式等）将在后续文章中单独展开。

## 汇总对照

| 手段 | 消除/减少的中断类型 | 额外收益 |
|------|---------------------|----------|
| CPU 隔离 + nohz_full | tick、调度 IPI、抢占、RCU IPI | 执行流确定性 |
| "关中断"（用户态） | 外设 IRQ（重定向或经轮询消除） | — |
| 大页 + 预分配 | 运行期 page fault | TLB miss 消除 |
| Onload / bypass | 硬中断、softirq、syscall | 零拷贝、零上下文切换 |

隔离和大页针对"周期性/结构性中断"，bypass 针对"事件驱动的中断"，两者相互独立，低延迟系统通常需同时采用。

---

> **小结**：用户态无法直接关闭中断，只能减少中断源、调整中断投递位置。隔离与大页消除结构性中断，bypass 消除事件驱动的中断，本质是以持续的 CPU 占用换取延迟的确定性与降低。
